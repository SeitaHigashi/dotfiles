## What this repository is

NixOS configuration for the single bare-metal server `seita-nixos-baremetal`. It runs on ZFS (SSD×1 +
HDD×2 mirror) and the disk layout is declared with disko. As a home server it hosts a Minecraft server,
a monitoring stack and local LLMs. Design rationale, measurements and incident reports live in `docs/`;
[README.md](README.md) is the table of contents.

## Where documentation goes

History, measurements and procedures go in `docs/`, not in `.nix` comments. The placement table is in
README.md ("Where things go"). In short:

- A `.nix` comment states **only the constraint on that line** ("measured ceiling, do not raise"), briefly,
  with a `docs/...` pointer for the rest.
- **When you change a `.nix` file, update the docs it points to in the same commit** — especially numbers
  (VRAM, context limits, ports). Docs drifting out of date is the main risk of this layout.
- When you add a doc, add it to the README.md index.
- Commented-out configuration stays in the `.nix` next to a short "how to re-enable" note (the user's
  rule: disable reversibly, don't delete).

## Commands

```bash
# Everyday rebuild (on the host; the user runs switch — sudo required)
sudo nixos-rebuild switch --flake /etc/nixos

# Evaluation check without touching disks — run this after every change
nix eval --raw .#nixosConfigurations.seita-nixos-baremetal.config.system.build.toplevel.drvPath

# Build without switching
nix build --no-link .#nixosConfigurations.seita-nixos-baremetal.config.system.build.toplevel

# Update flake inputs (bumping nixpkgs requires checking ZFS kernel support)
nix flake update
```

The configuration name equals the hostname, so `--flake /etc/nixos` may omit `#<name>`.

A fresh install uses `scripts/install.sh` (run on the ISO). `scripts/disks.env` is the only file a user
edits; `machine.nix` is generated from it ([runbooks/install.md](docs/runbooks/install.md)). There is no
test suite.

## Structure essentials

- **`machine.nix` is the only place for machine-specific values.** Generated by `install.sh`; other modules
  read it with `import ../machine.nix` (not via module arguments). Disk by-id paths, hostId, user, static IP,
  `nixPool`, `arcMaxBytes`, … Never hard-code host-specific values elsewhere.
- The `modules` list in `flake.nix` is the only entry point. A new module must be added there.
- **stable/unstable split**: the base is `nixos-25.05`. Only leaf packages listed in `modules/unstable.nix`
  come from `nixpkgs-unstable` (`pkgs.unstable.*`). Pulling the kernel, kernel modules (ZFS, NVIDIA),
  systemd or glibc from there makes the system unbootable ([nixpkgs-channels.md](docs/nixpkgs-channels.md)).
- `disko/default.nix` generates partitions, pools, datasets and `fileSystems`, so `hardware-configuration.nix`
  is generated with `--no-filesystems` and has no `fileSystems`.

## Before you touch things

Each item has its full story in the linked doc; the one-liner is what must not be forgotten.

- **A dataset added to `disko/default.nix` is not created on a running system.** `switch` only generates the
  mount unit; the mount then fails and the host **drops into emergency mode** (2026-08-25). Run `zfs create`
  by hand first, and switch from a console or `tmux` — adding a mount restarts `zfs-import-<pool>.service`
  and unmounts everything on that pool, including `/home` (your SSH session)
  ([zfs-operations.md](docs/runbooks/zfs-operations.md)).
- **Never add a single-SSD `special` vdev to dpool** — losing the SSD loses the whole HDD mirror.
- Never change `networking.hostId` after install. Never raise `system.stateVersion = "25.05"`.
- **Never set `nixpkgs.config.cudaSupport = true`** (rebuilds all of nixpkgs, no binary cache). Enable CUDA per
  package.
- Pin the FTB modpack with `FTB_MODPACK_VERSION_ID` (`Restart=always` would otherwise auto-update it).
  Minecraft heap + `arcMaxBytes` must stay below physical RAM ([minecraft.md](docs/services/minecraft.md)).
- **Resource limits for podman containers do not work via `systemd.services.podman-*.serviceConfig`** — conmon
  moves the container into `machine.slice`. Use `--cgroup-parent` and put weights on `systemd.slices`;
  `IOWeight` is ineffective on ZFS ([resource-priority.md](docs/resource-priority.md)).
- **`allowUnfreePredicate` is defined only in `modules/unfree.nix`** (a function; two definitions collide).
  A package can turn unfree when it moves to unstable (open-webui did).
- After an NVIDIA driver version change, **reboot** — switch alone gives `Driver/library version mismatch`.
- After changing `m.hostName` or `tailnetSuffix`, **restart `tailscale-serve` by hand**; the unit doesn't change,
  so switch won't restart it. Renaming the host has three more traps ([network.md](docs/network.md)).
- Secrets go through agenix (`secrets/*.age`, add the key to `secrets/secrets.nix`); never write a secret into a
  Nix expression. The Grafana admin password is the one manual exception ([secrets.md](docs/secrets.md)).
- Grafana dashboards and alert rules are provisioned read-only: edit the JSON / Nix, not the UI. Datasource UID
  `victoriametrics` is fixed; alert rules need an explicit `uid`; MetricsQL cannot use `\.` (write `[.]`);
  removing a rule needs a one-off `deleteRules` switch ([alerting.md](docs/services/alerting.md),
  [runbooks/monitoring.md](docs/runbooks/monitoring.md)).
- Network: HTTP services go through Tailscale Serve; Grafana 3000 and Open WebUI 8080 are **not** open on
  tailscale0. Open WebUI must sit at the root path; n8n uses its own port and no `N8N_PATH`; beyond SSH, only
  Minecraft (25565) and n8n (5678) are open to the LAN. The full evaluated port list is in
  [network.md](docs/network.md) — re-evaluate it rather than trusting a remembered list.
- `switch` does not restart units whose unit file did not change, and never frees resources held by
  already-running processes — say which units still need a restart when reporting a change.
